> [!TIP]
> **AI에게 "잘 해줘"라고 하지 않습니다. "무엇이 통과하면 끝인가"를 먼저 정합니다.** 요구를 인터뷰해 수용 기준으로 바꾸고, 갈래를 나눠 모델별 워커에게 병렬로 맡기고, 구현하지 않은 에이전트가 막아야 할 입력으로 직접 때려 봅니다. 사람은 판단과 승인만 합니다.

```mermaid
flowchart LR
    P["① PLAN<br/>요구 인터뷰<br/>수용 기준 확정"] --> F["② FAN-OUT<br/>코디네이터가 갈래 분해<br/>모델별 병렬 워커"]
    F --> V["③ VERIFY<br/>구현자 ≠ 검증자<br/>막아야 할 입력으로 타격"]
    V --> G{"④ GATE<br/>되돌릴 수<br/>없는 변경?"}
    G -- "예" --> H["사람 승인<br/>운영 배포 · DB · 외부 발송"]
    G -- "아니오" --> S
    H --> S["⑤ SHIP<br/>스위치 OFF 배포<br/>1건씩 · 30분 감시"]
    S -. "반복된 실수 → 규칙 한 줄로 코드화" .-> P
    classDef s fill:#0077B6,stroke:#14B8A6,color:#fff;
    classDef g fill:#14B8A6,stroke:#0077B6,color:#fff;
    classDef h fill:#EA4335,stroke:#B91C1C,color:#fff;
    class P,F,V,S s;
    class G g;
    class H h;
```

<kbd>Plan</kbd> → <kbd>Fan-out</kbd> → <kbd>Verify</kbd> → <kbd>Approve</kbd> → <kbd>Ship</kbd> — 하루를 닫을 때는 <kbd>/퇴근보고</kbd> 한 번으로 그날의 세션 로그와 git 이력을 교차 검증한 보고서가 나옵니다.

**기획 원칙 — 검증 표면적을 줄인다.** 검수 비용은 대략 화면·상태·경로의 곱으로 늘어납니다. 그래서 요구 N개를 화면 N개로 만들지 않고, 빈·로딩·에러·권한 상태를 같은 패턴으로 묶고, 같은 일을 하는 경로를 하나로 줄입니다.

$$\text{검수 비용} \approx \text{화면 수} \times \text{상태 수} \times \text{경로 수}$$

**원칙 체크리스트** — AI 에이전트가 매 작업에서 지키는 규칙입니다.

- [x] **확인한 것만 말한다** — "됐다"는 직접 본 것만, 무엇으로 확인했는지 함께 적는다
- [x] **존재 확인 ≠ 작동 확인** — 게이트·필터는 막아야 할 입력으로 직접 때려 본다
- [x] **구현자와 검증자를 나눈다** — 다른 에이전트가 다시 검증한다
- [x] **운영 변경은 1건씩** — 기능 스위치를 끈 채 배포하고, 반영할 때마다 30분 감시한다
- [x] **시크릿은 값이 아니라 위치·종류만** 다룬다
- [x] **반복된 실수는 메모리가 아니라 훅 규칙으로** 굳힌다
- [x] **화면·상태·경로를 통합**해 검수 비용을 줄인다

> [!CAUTION]
> **되돌릴 수 없는 작업은 AI에게 맡기지 않습니다.** 운영 배포, 운영 DB 쓰기, 강제 푸시, 외부 발송은 사람 승인 없이 실행하지 않는 것이 규칙입니다. main 강제 푸시·운영 자원 삭제·비밀정보 출력처럼 되돌릴 수 없는 명령은 훅이 자동으로 차단합니다.
